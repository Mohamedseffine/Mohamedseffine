## Featured Projects

### 01Blog

A full-stack social blogging platform built with Angular and Spring Boot. It includes JWT authentication, posts and comments, reactions, follows, media uploads, reporting and moderation, admin tooling, rate limiting, and real-time notifications over WebSockets/STOMP.

→ [Repository](https://github.com/Mohamedseffine/01Blog)

### LocalServer

A minimal HTTP/1.1 server written from scratch in Java using a single-threaded NIO Selector. It implements HTTP parsing, chunked transfer encoding, static files, uploads, CGI, sessions, routing, redirects, metrics, custom error pages, and path-traversal protection.

→ [Repository](https://github.com/Mohamedseffine/localserver)

### Real-Time Forum

A Go full-stack forum using REST APIs and WebSockets for live chat and notifications, with authentication, middleware, rate limiting, and SQLite persistence.

→ [Repository](https://github.com/Mohamedseffine/real-time-forum)

### Delimma.js

A lightweight JavaScript framework built from scratch to explore how frontend frameworks work internally. It includes a virtual DOM abstraction, component rendering, state management, routing, and a custom event system.

→ [Repository](https://github.com/Mohamedseffine/mini-framework)

### Multiplayer Bomberman

A real-time multiplayer game with a Node.js authoritative server and a custom JavaScript frontend framework. The server validates game state, movement, bombs, collisions, power-ups, and match lifecycle while clients communicate through real-time networking.

→ [Repository](https://github.com/Mohamedseffine/Bomberman-DOM)

### 0-Shell

A minimalist Unix-like shell written in Rust, implementing core commands and filesystem operations without relying on external shell binaries. Built to understand command parsing, process behavior, filesystem interaction, and Unix conventions.

→ [Repository](https://github.com/Mohamedseffine/0-Shell)

### More Experiments

I also maintain projects exploring GraphQL, networking, Rust, Go, Linux, Git internals, browser games, and security research. Some repositories are deliberately small because occasionally the best way to understand a system is to rebuild a tiny version of it.
